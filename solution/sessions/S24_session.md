## ⚠️ Прочитай перед началом

Исполнитель — агент. Находки поставляет куратор: тестирует CLI руками (сценарии ДЗ-02/ДЗ-03 — тул run_sql, retrieval + стриминг, --quiet, пайпы, деградации) и пишет результаты в чат. Цикл сессии на каждую находку:

1. **Приём**: находка фиксируется в журнале (раздел «Задачи», Task-запись) дословно — сценарий, ожидание, факт;
2. **Воспроизведение**: точная команда или падающий тест ДО фикса; нет воспроизведения — нет фикса;
3. **Квалификация**: баг (фикс) | не баг (обоснование из канона S00/ADR/prd, решение за куратором) | вне скоупа (BL-NN в solution/backlog/);
4. **Фикс**: минимальная правка + регрессионный тест, один находка-коммит;
5. **Прогон**: полный набор + make check зелёные.

Сессия закрывается, когда список находок куратора исчерпан (все исправлены или квалифицированы), make check зелёный и REVIEW-GATE пройден на накопленный диапазон сессии.

Сознательно НЕ делается: новые фичи и улучшения «заодно» (→ BL-NN); рефакторинг без бага под ним; изменения контрактов портов/схемы/ER (если находка этого требует — сначала ruling в этой сессии и точечный canon-check, потом код).

### Правила для исполнителя

1. Ни один фикс не коммитится без воспроизведения: падающий до фикса тест (юнит/интеграционный, остаётся в наборе) или точная команда-воспроизведение из находки. «Каждый Critical закрывается регрессионным тестом» (AGENTS.md DoD) — здесь распространяем на ВСЕ функциональные фиксы, не только Critical.
2. Одна находка — один коммит (атомарность; сообщение — WHY и ссылка на сценарий тестирования).
3. Находки вне скоупа исправления (новая функциональность, экономика/роутинг, V3+) — BL-NN в `solution/backlog/`, в сессию не тянем.
4. Спорная находка («не баг, а ожидаемое поведение») — не молчать: письменная квалификация с обоснованием из канона в отчёте сессии; финальное решение — за куратором.
5. Фиксы в retrieval/стрим-контуре (cli.py, openai_provider.py) прогонять вместе с `test_streaming.py` и `test_retrieval_flow.py`, а не только целевым тестом — контракт S19 (StreamChunk/StreamFinal, ретраи только до первого чанка, D-022) легко задеть.

### Task 1: журнал находок и квалификация

Вести здесь: находка (дословно от куратора) → воспроизведение → квалификация → ссылка на Task-фикс/BL/отклонение. Каждая строка датирована.

**Находка #1 (куратор, 2026-11-21, пакет из 4 прогонов `--retrieve --user u_logist`)**: «как-то странно выглядит — ни для кого ничего не находит или не знает как искать». Прогоны: DE/октябре — SQL+пояснение (норма); RU/октябре — SQL плюс галлюцинация «Результат: 1»; KZ(с опечаткой)/октябре — отказ с оговоркой «нет выдержек с данными из campaigns»; KZ/всего — отказ «в контексте знаний отсутствует таблица orders».

Воспроизведение: `repro_retrieval_s24.py` (временный диагностический скрипт, не коммитится) — корпус знаний (21 документ) + топ-12 с оценками для каждого из 4 вопросов, поиск под `u_logist` на живом pgvector + эмбеддер шлюза.

Квалификация — пакет распался на три разных дефекта:

- **(а) retrieval теряет ключевые документы — БАГ**: `RETRIEVAL_TOP_K=5` на корпусе из 21 документа — для 3-табличной цепочки (customers+orders+campaigns) структура вопроса требует DDL всех таблиц + ребро + few-shot + глоссарий ≈ 7–8 документов; в прогоне «...Кзахстана... всего» `ddl:orders` был 7-м (мимо), модель честно ответила «таблицы нет» — deny-by-default сработал правильно на неполном контексте. Смена одного слова («в октябре» → «всего») пересортировала топ-5. Прежний комментарий константы мицитировал ADR-003: «ранжирование топ-5» в каноне — про пути графа в plan_joins (FR-2, ADR-006), не про retrieval. → Фикс в Task 2.
- **(б) галлюцинация результата — БАГ (answer integrity)**: модель retrieval-контура не имеет канала исполнения SQL, но выдала «Результат: 1» как выполненный ответ. Причина: контракт промпта не запрещает выдуманные результаты; плюс формулировка «Если данных для ответа в контексте нет — скажи честно» читается малой моделью как «нет строк данных → отказ» (прогоны КЗ). → Фикс в Task 3.
- **(в) ожидание исполненных чисел от `--retrieve` — НЕ БАГ**: retrieval-контур ДЗ-03 по плану отдаёт SQL + пояснение (исполнение — тул-контур ДЗ-02: та же команда без `--retrieve`; узел execute_sql в FSM — веха V4). Квалификация зафиксирована; решение за куратором.
