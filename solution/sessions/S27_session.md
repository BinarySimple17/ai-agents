## Задачи

### Task 1: Сквозной happy-path — trace-артефакт ДЗ-05

Живой прогон полного конвейера на каноническом вопросе вехи (например, «клиенты,
пришедшие из рекламы» или «Сколько заказов у клиентов из РФ?»): FSM-режим CLI,
ConsoleTracer (S21) пишет этапы; зафиксировать файл-трейс: вопрос → допущения →
JoinPlan → SQL → валидация → ответ (с допущениями first-touch/usage_notes,
стоимостью). Это «Пример выполнения» из hw-plan §5.

**✅ Самопроверка:**

```bash
make infra-up && make infra-migrate && make sync-graph && make index-knowledge
uv run python -m apps.cli "клиенты, пришедшие из рекламы" --<fsm-флаг>   # полный ответ; трейс-файл в hw-05/
```

---

### Task 2: Сцены ветвлений — clarify (interrupt) и retry

(1) Неоднозначный вопрос (равные кандидаты пути) → interrupt → ответ пользователя
со stdin → тот же прогон завершается полным ответом (живая проверка checkpointer
S08 на Valkey). (2) Сцена самокоррекции: вопрос, где первая генерация падает
(например, код страны 'Russia' vs сид 'RU' — известный кейс S13/S24) → валидация/
execute ловит → diagnose → регенерация → ответ. Трейсы — в hw-05/.

**✅ Самопроверка:**

```bash
uv run python -m apps.cli "<неоднозначный вопрос>" --<fsm-флаг>   # interrupt показан, ответ пользователя доводит прогон
uv run python -m apps.cli "Сколько заказов у клиентов из России?" --<fsm-флаг>   # retry-цикл виден в трейсе, финальный ответ честный
```

### Task 3: Сцена deny — «премии» без прав HR

таблиц и без подтверждения существования (S9 hw-01). Трейс — в hw-05/. Это сцена
deny из hw-plan §5.

**✅ Самопроверка:**

## Ловушки

1. **Прогон на холодной БД без сидов/синка графа** — план_joins не найдёт рёбер и
   уйдёт в no_path: порядок обязателен (infra-up → migrate → sync-graph →
   index-knowledge), это же напиши в README (воспроизводимость для проверяющего).
2. Локальный LM Studio — одна модель на все роли (D-020): эскалация «уровень вверх»
   в трейсе не сменит модель — это ограничение стенда, а не баг; зафиксируй в README,
   чтобы не гоняться за фантомом.
3. reasoning-модели: ответ может уйти в reasoning_content (D-021) — если узел падает
   на JSON-контракте, это уже закрыто guard'ом S03; новые формы — фикс + регресс
   (правило 5), не «перепробовать промпт».
4. Не подменяй живые прогоны юнит-фейками: layer-3 этой сессии — именно живой шлюз;
   если он недоступен — стоп и запись в progress.md, а не «проверено тестами».
5. Сцена deny: проверяй ПОЛЬЗОВАТЕЛЬСКИЙ текст ответа, не трейс — служебный канал
   трейса имеет право на детали (S11-ловушка 3), пользовательский — нет.
6. Слияние milestone/v4 дальше (dev/main) — только по явной команде владельца (D-031);
   эта сессия не мержит веху наружу.
