### Правила для исполнителя

1. Ветка `harness/docs-target-vs-fact` от `milestone/v4`; merge — в `milestone/v4` (D-031).
2. **Пометка «цель / факт»:** в свёртках и схемах целевой контур помечается явно («целевое, не
   построено: …»), as-is описывается по коду. Новых требований нет — тексты приводятся к уже
   принятым решениям и к факту.
3. **ADR не переписываются задним числом.** Правится текст, противоречащий уже принятому решению
   (например, §3 ADR-009 — по решению владельца в FIX-005); смысл решения не меняется → версия не
   растёт, в истории — строка «редакционная правка». Если правка меняет смысл — новая версия и
   решение куратора до правки.
4. **`prd.md` — живые требования:** сцена 3 меняет формулировку, не требование FR-6.
5. **`feature_list.json`:** только тексты `description`/`behavior`/`notes`; `state` и `evidence` —
   руками не менять. Для feat-013 прогнать её verification-команду и записать результат в отчёт
   сессии и `progress.md`.
6. Каждое закрытое противоречие — статус в `solution/FIXES.md` (FIX-012…FIX-016).
