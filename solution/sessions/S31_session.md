1. `domain.validate_sql` требует `skeleton`, `join_plan`, `skeleton_hash`
   (`sql_validation.py`, 181–190) — в тул-лупе их нет. Нужен режим «свободного SQL»: та же форма,
   функции и ACL, без сверки скелета.
2. Для ACL нужна identity с правами. `cli-dev` в сидах (`0003_demo_data.py`, 143–146) прав не имеет,
   поэтому команда из `hw-02/README.md:122` (`--plain` без identity) после закрытия дыры будет
   отклонена. Значит, команды артефактов ДЗ-02/03 получат `--token` — утверждение аудита
   «артефакты не меняются» верно только с этой поправкой.
3. Системный промпт тул-контура перечисляет всю схему, включая `employees.salary` и `bonuses`
   (`cli.py`, 146–153) — для identity без прав HR этих таблиц в мире агента быть не должно
   (S00 контракт 3, ADR-005).

Варианты (аудит): **A** — валидатор и права внутри `RunSqlTool`; **B** — дефолт `--fsm`, тул-контур

для любого режима; артефакты ДЗ-02/03 остаются тул-контуром (меняется только identity в командах).
B сам по себе тул-контур не защищает.

### Правила для исполнителя

1. Ветка `harness/single-execution-gate` от `milestone/v4`; merge — в `milestone/v4` (D-031).
2. **Один валидатор — две политики.** Общая часть (функции, таблицы, колонки, звёзды, LIMIT —
   `_check_functions`, `_check_tables`, `_check_columns`, `_check_stars`, `_enforced_limit` в
   `domain/sql_validation.py`) вызывается обоими входами: `validate_sql` (FSM, со скелетом) и новым
   `validate_free_sql` (без скелета); в сервисе — `ValidateSqlService.validate_free(...)`. Вторую
   копию ACL в туле не заводить: правки валидатора должны доставляться в оба контура сразу.
3. **Identity — только из проверенного токена** для любого контура, исполняющего SQL (ruling R4
   ARCH-GATE S05: сырой user_id verify не проходит). Права — `PermissionStore.fetch_rights` +
   `data_catalog()` на каждый прогон. Точный канал identity (упразднить `--user` или оставить
   только для retrieval с запретом исполнения) — вопрос ARCH-GATE.
4. **Fail-closed и честно:** отказ валидатора → Observation с классом ошибки, без деталей
   инфраструктуры (S9); токен отсутствует или неверен → отказ до первого LLM-вызова; права
   недоступны → отказ, а не «пустой мир молча». Подсказка модели при отказе называет только то,
   что есть в правах этого пользователя.
5. **Артефакты ДЗ-02/03** (`hw-02/README.md`, `hw-03/README.md`, трейсы `hw-03/`) — править только
   после подтверждения куратора, что они не заморожены сдачей. ДЗ-03 сдаётся 08.12 — поэтому окно
   сессии заканчивается 04.12.
6. Канон — в том же коммите, что и код: ADR-002 (поправка: тул-контур проходит тот же рубеж),

## Задачи

### Task 1: Режим «свободного SQL» в валидаторе (domain + services)

- `domain/sql_validation.py`: `validate_free_sql(audit, *, permissions, data_catalog, row_limit) -> ValidationVerdict`
  — форма уже проверена в services (`_parse_tree`); здесь функции, таблицы, колонки, звёзды, LIMIT;
  сверка скелета не выполняется. Общая часть — общие хелперы для обоих входов.
- `services/validate_sql_service.py`: `validate_free(sql, *, permissions, data_catalog, row_limit) -> ValidateSqlResult` —
  тот же парсинг и обход; при ok — разворот звёзд и внешний LIMIT (к исполнителю уходит только
  переписанный текст, как в FSM).
- Тесты — новый `src/tests/unit/test_validate_free_sql.py`: DML, вторая инструкция, `SET`, функция вне
  allow-list, служебная схема, неизвестный тип узла → отказ; таблица вне прав → denied; несуществующая
  таблица → hallucination; `SELECT *` по таблице с явным списком колонок разворачивается; ok-запрос
  получает LIMIT ≤ 1000.

## Ловушки

1. **Вторая копия ACL в туле** — запрещена (правило 2): иначе каждое усиление валидатора будет
   защищать только FSM, и дыра вернётся.
2. **«Пустой мир молча»**: у identity нет прав — retrieval пуст, а SQL обязан отклоняться с ясной
  причиной, а не возвращать «0 строк».
3. **Модель видела всю схему в промпте** — после фильтрации промпта по правам она может
  «вспомнить» таблицу из few-shot: few-shot и глоссарий уже фильтруются по правам в retrieval (S06);
  проверить живьём под u_logist.
4. **Denied-отказ в цикле**: модель не должна «уговаривать» валидатор повторами — контур формулирует
  отказ сразу; кап `MAX_TOOL_CALLS` остаётся страховкой.
5. **Стриминг**: отказ приходит после напечатанной преамбулы — это штатный исход
  (`_stream_outcome`), не добавлять второй канал печати.
6. **Артефакты чужих вех**: hw-02 и hw-03 — артефакты V1/V2; правка без подтверждения куратора —
   обход условия «сданное не трогаем».
7. **Джойны в свободном режиме не сверяются с реестром** (нет плана): обе таблицы обязаны быть в
   правах, но выдуманная связь между своими таблицами возможна — остаточный риск записать в
   поправку ADR-002.
