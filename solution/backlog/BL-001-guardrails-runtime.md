# BL-001 — Guardrails времени выполнения (I1 длина, I2 санитайзер, rate-limit) не покрыты фичами

- **Статус:** открыт
- **Дата:** 2026-11-15
- **Сессия-источник:** harness (red-team аудит архпакета, FIX-005)
- **Приоритет:** P2
- **Назначение:** BL-047 — вход в прод-контур (веха V5 по D-040): первый долгоживущий процесс — `agent-api`; перенесено из S18 (ранее — Streamlit-демо, снято D-040)

## Что обнаружено

security §3 обещает guardrails «в коде агента»: I1 лимит длины вопроса
(`GUARD_MAX_INPUT_CHARS`), I2 санитайзер control/zero-width символов, per-user token
bucket (`RATE_LIMIT_USER`, 429 + Retry-After). Ни одна фича feature_list (feat-001…019)
это не закрывает — при исполнении плана возник бы дрейф «док обещает — код не имеет»
(R-P2). Для v1 (локальный CLI, один пользователь) некритично; первый реальный
потребитель — долгоживущий процесс (Streamlit-демо / источник `/metrics`, открытый
вопрос ADR-010).

## Почему вне скоупа сессии

Аудит документации; на приёмку harness-сессии и вех V1–V4 не влияет.

## Закрытие (заполняется при закрытии)

Вариант: задача в сессии BL-047 (D-040: `agent-api` — первый долгоживущий процесс; Streamlit-демо
не строится); до тех пор — заметка в security §3 «v1 — CLI, применяется при долгоживущем процессе».
