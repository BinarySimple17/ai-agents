## Что обнаружено

Старт-гейт сессии (D-023) закрывает дыру «ARCH-GATE задним числом» и консистентность файла
сессии, но работа **вовсе без файла сессии** по-прежнему проходит `make check`: start-фаза
без активной сессии — WARN, exit 0 (осознанный инвариант рестартуемости свежего клона,
`./init.sh` — verification feat-001), а end-фаза делает fallback на последнюю архивную
сессию с заполненными гейтами. Механической проверки «каждый коммит с изменениями кода
ссылается на файл сессии» нет — D-023 честно фиксирует это как частичное закрытие дыры.
Вариант усиления: pre-commit-гвард, требующий в сообщении коммита ID сессии (например,
`S22: …`) и/или существования файла `solution/sessions/S22_session.md`; либо проверка в
`clean-state-check.sh` (грязное worktree без активной сессии = FAIL с явным allowlist).

## Почему вне скоупа сессии

Требует решения о компромиссе «дисциплина ↔ трение» (соло-исполнитель; коммиты доков и
harness-правки владельца не привязаны к сессиям) и не влияет на приёмку S22 — временной
порядок «canon-check до кода» и так поддержан красным make check.
