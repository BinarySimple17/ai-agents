# BL-022 — feat-022 (Streamlit-демо) без сессии-владельца, но блокирует feat-018

- **Статус:** открыт
- **Дата:** 2026-11-24
- **Сессия-источник:** S29 (триаж аудита 2026-11-23, находка B1)
- **Приоритет:** P1
- **Назначение:** V5 (ДЗ-06) — оформить сессию при планировании вехи; слот по D-032 — вторая половина декабря, до 16.01.2027

## Что обнаружено

В `feature_list.json` feat-018 зависит от feat-015 и feat-022. В `solution/sessions.md` сессия S18
зависит только от S15, в строке вехи V5 feat-022 упомянута с 2026-11-24 (триаж), но сессии с ролью
«закрывает feat-022» по-прежнему нет. По ADR-010 v1.2 источник `/metrics` — долгоживущее
Streamlit-демо, то есть без feat-022 сессия S18 не может выполнить своё behavior.

Все зависимости feat-022 (feat-008, feat-015, feat-019) в passing с 2026-11-22 — фича разблокирована
и не привязана к открытым работам V4.

## Почему не в текущей вехе

ДЗ-05 собрано без веб-интерфейса (hw-05 — CLI-прогоны); демо относится к вехам V4/V5 по D-032, но
его единственный потребитель — feat-018 (ДЗ-06).

## Что делать

При планировании вехи V5: `make new-session S=<ID> TITLE="Streamlit-демо" F=feat-022`, заполнить
нарратив, добавить сессию в граф и в зависимость S18; строку вехи V5 пополнить. Тонкий app: логика
в `application/services` + `composition`, модуль UI — только рендер (из описания feat-022).
