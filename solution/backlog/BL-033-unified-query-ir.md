# BL-033 — Единый IR (`QuerySpec`) для FSM и тул-контура

- **Статус:** открыт
- **Дата:** 2026-11-24
- **Сессия-источник:** S29 (триаж аудита 2026-11-23, стратегическая рекомендация)
- **Приоритет:** P3
- **Назначение:** V6 — точка роста (ADR-011, BL-013 «агент рядом» / BL-018 продакшен-фронтенд)

## Что обнаружено

`QuerySpec` спроектирован только для SAP (ADR-011), а PG-путь принимает свободные SQL-фрагменты
от модели. Отсюда тяжесть валидатора и ошибки именования: «объекта нет» с уровня БД (A4), несуществующая
колонка при правах `'*'` (A5), необходимость ребра перепланирования (A6). Аудит предлагает рассмотреть
единый IR для обоих путей и называет цену — выразительность.

## Почему не в текущей вехе

Симптомы закрываются точечно в S31–S34; IR меняет контракт генерации целиком и имеет смысл, когда
контракт ответа стабилизировался (после ДЗ-06, по D-032).

## Что делать

Не начинать до закрытия S31–S34. Вернуться при старте BL-013 или BL-018: вопрос — отдельный ADR
(варианты: свободный SQL + валидатор, как сейчас; IR только для аналитических агрегатов; полный IR
с потерей выразительности). До решения — не закладывать в планы вех. После S34 — точка пересмотра:
если симптомы A4–A6 вернутся, решение по IR поднимается раньше V6.

## Проектные ограничения для будущего ADR (зафиксированы fix-волнами S31, 1015fcb, 2026-11-25)

Семантика связи, которую IR обязан выражать — или осознанно ослабить с записью цены
(сейчас живёт в ADR-002 v1.6 §5 / ADR-006 v1.7 §4 + ~35 регрессий test_validate_free_sql.py;
детали — отчёт S31 REVIEW-GATE, 5 fix-волн ревью):

- связь = равенство колонок, задевающее присоединяемый источник и пересекающееся с
  уже присоединёнными, в конъюнктивном скелете ON (Or/Not/Case не утверждают связь);
- корреляция подзапроса = пара «внешняя таблица ↔ таблицы того же сравнения»;
  производный источник (CTE/подзапрос/LATERAL) в операнде/корреляции — fail-closed;
- несвязанный источник при ≥3 таблицах — fail-closed («соседние» пары произвольны);
- полу-соединение/скалярный подзапрос БЕЗ корреляции — вне сверки BY DESIGN (BL-045).

Асимметрия контуров (сознательная, унаследуется IR-миром): FSM сверяет структуру со
скелетом плана (`_check_skeleton` — рёбра плана уже из реестра, «связь» несёт план),
тул-контур — инвариантом по свободному SQL. IR для FSM = план + скелет, не второй разбор.
