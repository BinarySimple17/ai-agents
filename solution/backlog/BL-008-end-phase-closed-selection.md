## Что обнаружено

End-фаза `guard-subagents.sh` (после fix C1) при отсутствии стартованных (◐) сессий берёт
последнюю закрытую (✅) в корне / последнюю в `archive/` по `sort -V` (максимальный ID),
а не по порядку закрытия. Если в корне окажутся ДВЕ закрытые сессии — проверяется только
последняя, без WARN (симметрично ситуации I3 «несколько ◐», где WARN уже есть). Для
текущего репозитория безопасно (harness-сессии имеют старшие ID; feature-сессии страхует
strict verify-feature по feature-id), но при росте числа параллельных линий — латентная
дыра.

Варианты усиления: WARN при нескольких закрытых в корне (симметрично I3); выбор по mtime
(«последняя закрытая» буквально); проверка всех закрытых в корне.

## Почему вне скоупа сессии

Требует решения о семантике «закрываемая» (ID vs mtime) и не влияет на приёмку S23 —
сценарий двух одновременно закрытых сессий в корне на текущем соло-контуре недостижим.
