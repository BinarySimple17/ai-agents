## Что обнаружено

Нормализация `agent_permissions.columns` (CSV-текст БД → список колонок) существует
в трёх местах с разной семантикой:

1. `pg_permission_store._normalize_columns` (S05) — **fail-closed**: пустой/повреждённый
   CSV → `RightsUnavailableError` (отказ, не тихое сужение прав); `'*'` литералом;
   дедупликация с сохранением порядка.
2. `plan_joins_service._normalize_permissions` (S09) — **lenient**: пустые элементы
   молча отбрасывает (строка 693-708 на момент находки).
3. `apps/plan_joins_demo._permissions` (S09-демо) — **lenient**, standalone.

Рантайм-путь прав (FSM) теперь идёт через fail-closed адаптер; расхождение
неактивно, но при будущей правке R5-семантики (например, появлении непубличных
схем или строгого `'*'`-интерпретатора в S11) сервис и демо разъедутся с адаптером.

## Что делать

Переиспользовать одну реализацию (адаптер `PgPermissionStore` — единственный
источник; `plan_joins_service` получает нормализованные права из state, от его
собственного парсера остаётся только fallback для прямых вызовов сервиса; демо —
либо тот же парсер, либо явная пометка «демо-семантика»). Заодно решить судьбу
lenient-веток (сделать fail-closed единообразно).

## Обновление — S11 Task 2 (2026-11-22)

Валидаторная сторона закреплена (ruling R2 ARCH-GATE S11): `domain.sql_validation`
свой CSV-парсер не заводит — значение прав строго «список колонок», строка →
`ValueError` (fail-closed, тест `TestPermissionsContract`); нормализация остаётся
у адаптера `PgPermissionStore` (fail-closed S05, `'*'` литералом). Разворот `'*'`
в разрешённые колонки — валидатор (ADR-005 §4 п.2): '*'-разрешённая таблица
оставляет суб-звезду `t.*` (права и так открывают все колонки), явный список
подставляется в текст SQL к исполнителю, пустой список → deny.

fallback, `apps/plan_joins_demo`) с адаптером — вне S11, запись остаётся открытой.
