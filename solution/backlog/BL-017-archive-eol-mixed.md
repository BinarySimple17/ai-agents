## Что обнаружено

Репозиторий на Windows-чекахауте живёт с CRLF (`core.autocrlf=true`). Node-блок
`scripts/archive.sh` при анти-раздувании пересобирает раздел «Текущее состояние»
строкой с `\n`-джойнами (`rebuilt = "## Текущее состояние\n\n" + "> …\n"`), после
чего `solution/sessions.md` содержит смесь CRLF (остальной файл) и LF
(пересобранный раздел). Git при `git add` предупреждает «LF will be replaced by
CRLF»; диффы по строкам раздела всегда шумят. Класс известен и признан не
дефектом (см. scripts/README.md, примечание про `[FIX]`-вставки гварда) — запись
про опциональную унификацию, не про баг.

## Почему вне скоупа сессии

Косметика: проверки (`make check`, гварды, архивация) от смешанных EOL не зависят;
правка — одна функция в node-блоке archive.sh, не влияет на приёмку S28.

## Закрытие (заполняется при закрытии)

EOL-preserving работа в node-блоке archive.sh по образцу `readLines`/`writeLines`
из `scripts/close-session.sh` (детект eol по `\r\n`, `split(/\r?\n/)` /
`join(eol)`); `new-session.sh`/`close-session.sh` уже EOL-preserving — держать при
правках. Либо осознанный отказ: «git нормализует при коммите, не чинить».
