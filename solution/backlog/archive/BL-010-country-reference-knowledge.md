## Что обнаружено

Тул-контур ДЗ-02 не имеет retrieval, поэтому схема и значения справочников живут
в его `SYSTEM_PROMPT` (решение S13). Находка #2 S24: без кодов стран модель
угадывала литералы (`'Russia'` при сиде `'RU'`) и уверенно отвечала «0 клиентов
из РФ» при реальных 5. Минимальный фикс S24 — строка с кодами в `SYSTEM_PROMPT`
(`country = 'RU'/'KZ'/'DE'/'BY'`, `status = 'paid'/'shipped'/'cancelled'`, источник
— сид, миграция 0003) + караул «0 строк по справочнику → проверь SELECT DISTINCT».

В глоссарии знаний (`docs/glossary.md`, раздел «клиент из РФ») коды стран
упомянуты точечно (`'RU'`, `'DE'`), полного справочника справочников нет.

## Почему вне скоупа сессии

S24 — сессия QA-фиксов: минимальный фикс уже в промпте тул-контура, а перенос
знаний в глоссарий с реиндексацией — содержательная работа с ADR-003 (одно
место истины), которая имеет смысл только вместе с решением, куда смотрит
тул-контур в V4; решение владельца 2026-11-21: «сейчас достаточно промпта».

## Что предлагается (решение владельца: «сейчас достаточно в системном промпте»)

К вехе V4 (соединение retrieval с FSM — S04/interpret), когда контекст агента
начнёт собираться из векторной памяти, перенести коды справочников из
`SYSTEM_PROMPT` в курируемый справочный документ глоссария («Справочники:
страны RU/KZ/DE/BY, статусы заказов paid/shipped/cancelled») + reindex
(`make index-knowledge`), оставив в промпте только общее правило
«фильтр по справочнику вернул 0 строк → проверь SELECT DISTINCT».

Причина переноса: одно место истины (ADR-003 — знания в pgvector, не в коде);
сид-литералы в промпте и глоссарии разъедутся при первом расширении сида.
До V4 дублирование — осознанное: промпт тул-контура и так несёт схему (S13).
