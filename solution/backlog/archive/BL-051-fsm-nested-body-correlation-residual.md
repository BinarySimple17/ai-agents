## Что обнаружено

FSM-валидатор проверяет вложенные скоупы только по ACL: тела CTE/подзапросов/LATERAL
проходят те же правила таблиц/колонок (`sql_validation.py:25-26`, `:218-221`; тесты
`test_validate_sql.py:353-425` — window/LATERAL/DISTINCT ON/GROUPING SETS/UNION),
а сверка структуры (`_check_skeleton`, `sql_validation.py:485-524`) смотрит только корень:
FROM, JOIN-ы внешнего запроса (`_collect_joins` — `validate_sql_service.py:950-967`),
mandatory_predicates. Вложенные тела не сверяются ни с реестром, ни с планом: модель
может добавить во вложенное тело **любую таблицу в пределах прав пользователя — в том
числе вне JoinPlan — и связать её с другими на произвольном условии** (ACL-safe, но
таблица и условие связи выдуманы). Инвариант FR-2/ADR-002 «физически не может придумать
связь — свойство системы» (`prd.md:64`, `ADR-002:96-97`) выполняется для явных JOIN
скелета и **не** для вложенных тел.

**Проверено прогоном 2026-11-26** (FSM-валидатор без БД, в памяти; план
`orders → customers`, права на orders/customers/bonuses/campaigns):

| SQL | FSM | свободный вход |
|---|---|---|
| `WHERE EXISTS (SELECT 1 FROM bonuses b WHERE b.employee_id = o.customer_id)` — таблица вне плана, выдуманное условие | `ok` | `hallucination` («связь bonuses↔orders не существует в реестре связей — джойн придуман») |
| `WHERE o.id IN (SELECT b.employee_id FROM bonuses b JOIN campaigns ca ON b.employee_id = ca.campaign_id)` — вложенный JOIN без ребра | `ok` | `hallucination` |
| контроль: без прав на `bonuses` | `denied` | — |
| контроль: несуществующая таблица в теле | `hallucination` | — |

ACL вложенных тел держится; несверяемы — принадлежность таблиц плану и условия связи.

Проявление в корпусе S31/B2: LATERAL-смешанный скоуп — свободный вход HALLUCINATION
(fail-closed, `test_validate_free_sql.py:352-357`), FSM OK (`test_validate_sql.py:392-399`
— тело проверено, корень цел). Корневой UNION своих таблиц — свободный OK (`:389-391`),
FSM отказ (изменённый скелет, `test_validate_sql.py:416`).

Для сравнения: свободный вход сверял пары корреляций (механика
`validate_sql_service.py:404-781`) и сознательно не сверял semi-join/скалярный подзапрос
без корреляции (`sql_validation.py:288-292`; BL-045 закрыт D-040 — «честная граница»).
FSM не сверяет ни корреляции, ни semi-join.

## Почему вне скоупа (аудита и коммита удаления)

Зазор **предсуществует в FSM**; удаление тул-контура его не создаёт — но убирает более
строгую альтернативу (свободный вход с инвариантом на корреляции). Коммит удаления
не исправляет: residual остаётся действующим ограничением FSM (решение (a) ниже).

## Решение владельца (2026-11-26) — (a)

1. **Residual принимается; формулировка инварианта смягчается** в волне ревизий удаления
   (BL-048, шаг 2): «явные JOIN корневого скелета — рёбра плана (активный реестр); во
   вложенных телах (CTE, подзапросы FROM/WHERE, LATERAL) — только ACL: таблицы в пределах
   прав пользователя; принадлежность плану и условия связи не сверяются». Строки канона:
   `prd.md:64` (FR-2), `ADR-002:97`, `ADR-006:37,:48,:192,:197`; абзац `ADR-006:199-232`
   (v1.5–v1.8) описывает проверки свободного входа — переписать под факт FSM;
   `security.md:130`, `ARCHITECTURE.md:54`, `RISKS.md:38`, `model-card.md:81,:113`
   (`hw-04/README.md` — замороженный артефакт, не трогать).
2. **В коммит удаления — pin-тесты residual** в `test_validate_sql.py`: оба кейса таблицы
   выше + LATERAL-смешанный (существующий `:392-399`), с пометкой «known residual,
   BL-051»: при будущем варианте (b) они переворачиваются осознанно.
3. **Усиление — отдельным коммитом после removal** (решение владельца 2026-11-26):
   правило «все таблицы запроса ⊆ план» в `_check_skeleton` (`sql_validation.py:485-524`;
   `audit.tables` уже собирает тела CTE — `:145-146`) + 2 регрессионных теста (кейсы
   выше → `hallucination`, ретрай оправдан). Проверка на юнит-корпусе 2026-11-26 (правило
   в памяти, без записи в репо): 841 passed / 0 failed (78 тестов свободного входа вне
   правила), правило сработало 27 раз — все в уже отклоняемых кейсах. После правила
   residual сужается до условий связи между таблицами самого плана; формулировку в
   каноне той же правкой дополнить («вложенные тела: таблицы ⊆ план + ACL»). Проверено
   только на юнит-корпусе, не на eval-сете.
4. **Риск и eval:** запись «выдуманная связь во вложенном теле» с митигациями (ACL
   вложенных тел, pin-тесты, M1) — S36 Task 7; eval/red-team кейс — BL-025; триггер
   пересмотра — первый случай злоупотребления формой (принцип BL-045).
5. **Для D-041:** механика S31 (пары/корреляции, `validate_sql_service.py:404-781`)
   после удаления — в истории (`git log -S_assert_tie_pairs`, коммит `45d606a`); для FSM
   вариант (b) дешевле через «таблицы ⊆ план» (пункт 3), а не порт механики пар.
