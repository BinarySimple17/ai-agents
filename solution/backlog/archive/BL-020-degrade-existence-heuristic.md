# BL-020 — Санитайзер существования degrade: эвристический список стемов не исчерпывающий

- **Статус:** закрыт (2026-11-22: реализовано в S27 — стемы + бит-тесты) <!-- открыт | закрыт (ГГГГ-ММ-ДД: реализовано в feat-0XX / отказано: причина / перенесено: куда) -->
- **Дата:** 2026-11-22
- **Сессия-источник:** S15 (REVIEW-GATE re-review — Minor 1)
- **Приоритет:** P3

## Что обнаружено

Санитайзер S9 отказов degrade (`degrade_service._EXISTENCE_MARKERS`) — стем-эвристика:
`"имеютс"` не покрывает единственное число («имеется запись о бонусах» проходит);
«обнаружены», «встречаются», «найдены» тоже не покрыты. Свойство подхода, не регрессия
волны 2: список по определению не исчерпывающий, вторая линия защиты (промпт без чужих
имён — R8; deterministic-шаблон-fallback) остаётся.

## Почему вне скоупа сессии

Не блокирует merge (re-review «Yes»); расширение списка — постоянный трейд-офф
false-positive (шаблон вместо текста модели — безопасное направление) vs лексический
охват; систематическое решение (морфологический анализатор) — отдельная задача.

## Закрытие (заполняется при закрытии)

2026-11-22, S27 (сборка ДЗ-05 — deny-сцена идёт в артефакт сдачи, план сессии
предписывал закрыть запись здесь): в `_EXISTENCE_MARKERS` degrade_service добавлены
стемы «имее» («имеется» ед.ч. — «имеютс» не матчится), «обнаруж», «встреча»,
«найден» (покрывают все формы словоизменения); бит-тесты в TestDegradeSanitizer +
гвард шаблонов fallback_text расширен теми же стемами. Систематическое решение
(морфологический анализатор) остаётся за пределами — при появлении требований
аудита S9; вторая линия защиты (R8-промпт + шаблон-fallback) не менялась.
