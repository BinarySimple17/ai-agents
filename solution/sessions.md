# План-сессий: Text-to-SQL аналитик данных (вехи V1–V6 = ДЗ-02…06)

> Каждая сессия — самодостаточный модуль для автономного агента-исполнителя.
> Формат: шапка (Этап | Владелец | Зависимости | Оценка | Статус) → ⚠️ Прочитай → Правила исполнителя →
> Предусловия → Задачи (с ✅ Самопроверками) → Критерии приёмки → Ловушки → Отчёт.
> **Источник истины при конфликтах — S00** (`sessions/S00_session.md`), затем `docs/adr/`, затем сессии, затем `docs/`.
> Жизненный цикл и правила — `solution/README.md`. Оценка — исторический номинал в часах.
> Базис планирования (решение владельца 2026-11-26): **1 ч оценки ≈ 10% недельного лимита
> токенов** — ставка для чистой сессии (без ревью-волн, переделок, незакрытых хвостов);
> осложнения — риск-множитель поверх ставки. Калибровка S31: номинал 1.5 ч → фактически
> 2.5+ ч и ~30% недельной квоты (×2 к базовой), хвост → BL-046.

Порядок исполнения задаётся вехами V1–V6 (порядок ДЗ, FIX-003), а не нумерацией S-NN; приоритет P0 — сессии ближайшей вехи (например, S19 — P0: дедлайн ДЗ-03 07.12 раньше P0-сессий вехи V4).

1. Не трогать файлы чужого трека (карта владения выше); общие файлы — только дословно из S00 или по согласованию.

3. Обнаруженное вне скоупа сессии — файлом в `solution/backlog/` (BL-NN), не в чат и не в чужую сессию.
4. Статусы сессий обновляются в таблице выше по факту закрытия; «Текущее состояние» — при clock-out.
