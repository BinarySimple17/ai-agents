# ADR-002: оркестрация — state machine на коде (workflow-скелет с агентным ядром)

- **Статус:** Принято (v1.1, 2026-11-16 — карта решений: tier модели назначает код — стартовый по матрице ADR-007, эскалация по факту провала)
- **Дата:** 2026-11-14
- **Контекст принятия:** выбор способа организации цикла агента до описания узлов и схем
- **Связанные документы:** prd.md (§4 FR-1…FR-11), ADR-004 (декомпозиция — цикл шагов), ADR-005 (валидатор — главный рубеж), ADR-007 (эскалация при retry)

---

## 1. Контекст

Требования кейса: принимать вопрос, формировать SQL, выполнять, объяснять — при
ограниченном доступе и безопасном выполнении. Текст от LLM — не доверенный, поэтому
валидация должна стоять **до** выполнения и её нельзя перепрыгнуть. Одновременно
содержательные решения (однозначен ли вопрос, какое ребро графа, как декомпозировать,
как исправить ошибку) — семантические, их отдавать коду нельзя. Нужно выбрать, как
совместить оба требования в одной управляющей структуре.

## 2. Сравнение по осям

| Ось | Свободный ReAct-агент (LLM выбирает следующий инструмент) | Жёсткая цепочка (pipeline) | Workflow-скелет с агентным ядром |
|---|---|---|---|
| Кто управляет маршрутом | LLM каждый шаг | код, без ветвлений | код (граф переходов); LLM — содержимое узлов |
| Валидация не перепрыгивается | нет — модель может «забыть» вызвать валидатор | да, но нет retry-цикла | **да**: ребро `execute_sql` существует только из `validate_sql` |
| Dead loop защита | бюджет шагов + hope | не нужен | лимиты в коде (retry ≤ 3, кап 2 ₽) — детерминированно |
| Адаптация маршрута ко входу | максимальная | нулевая | модель может **укоротить** маршрут (уточнение) и ветвить (декомпозиция, deny), но не выйти за рельсы |
| Тестируемость | сценарная | юнит-тесты на цепочку | юнит-тесты на узлы + интеграционные на переходы |
| Трассировка | запутанная (полусвободные ходы) | линейная | каждый узел и переход — спан; сцены читаются из trace 1:1 |

## 3. Рассмотренные варианты

### Вариант A — свободный ReAct (например, `create_react_agent`)
Отвергнут. Ключевая дырка — безопасность как свойство дисциплины модели: валидация
существует, пока модель её вызывает. Для системы, где текст LLM не доверенный, а
ошибка валидатора = утечка данных, — недопустимо. Плюс dead loop защита становится
угадыванием (у модели нет своего представления об исчерпании бюджета).

### Вариант B — жёсткая цепочка без ветвлений
Отвергнут. Не выражает суть задачи: уточняющий вопрос — валидный исход, декомпозиция
включается по порогам, ошибка возвращает в генерацию. Pipeline с одинаковым маршрутом
на любом входе — это не агент и требует дополнительных механизмов поверх для каждого
ветвления, т.е. к варианту C с худшей структурой.

### Вариант C — workflow-скелет с агентным ядром ✅ **ПРИНЯТО**
Граф переходов — обычный код (LangGraph); узлы — функции, вызывающие application-сервисы;
ReAct-семантика (Reason → Act → Observe) развёрнута по узлам: каждый содержательный узел
есть Reason (вербализация перед действием) и Observe (результат инструмента в state).

## 4. Решение

**Оркестратор — state machine на коде (LangGraph): маршрутом управляет движок,
содержимым узлов — модель. Инструкции — тексту, контроль — движку.**

Карта решений — кто что решает:

| Решение | Кто принимает |
|---|---|
| Однозначен ли вопрос; допущения; уточнение или дальше | **LLM** — уточнение валидный исход |
| Какие таблицы и какое ребро графа (first-touch vs any-touch) | **LLM** по смыслу вопроса |
| Как декомпозировать тяжёлый запрос | **LLM** — строит DAG переменной длины во время выполнения |
| Какой SQL; как исправить после ошибки | **LLM** |
| Декомпозировать ли вообще | **код** (пороги T1/T2 — ADR-004) |
| Какая модель решает узел (tier) | **код** — стартовый tier по матрице ADR-007; эскалация по факту провала (`retry_count`) |
| Валидация, лимиты retry и бюджета, остановка | **код** |

Почему это агент, а не pipeline: **структура траектории зависит от входа и решений
модели** — один вопрос завершается уточнением, другой проходит 3 шага декомпозиции,
после ошибки `diagnose_error` даёт разные исправления. Модель формирует содержимое
каждого узла и может укоротить маршрут, но не выйти за рельсы. По строгой таксономии
(лекция: workflow — LLM в предопределённых путях кода; agent — LLM сам направляет
процесс) наш каркас — workflow-скелет с агентным ядром; баланс осознан:

> **детерминизм там, где корректность и безопасность; агентность там, где семантика.**

Два отличия от «голого» ReAct, сохранённые в узлах: Thought вербализуется на каждом
LLM-узле (~100 дешёвых токенов против целого повторного цикла при ошибочном вызове
инструмента) и Observation от каждого инструмента возвращается в state — цикл
самокоррекции `generate → validate → execute → diagnose → generate` замкнут внутри
машины, а не разведён по свободным ходам.

## 5. Последствия

**Положительные:**
- Безопасность — свойство структуры: валидатор стоит на единственном ребре к
  исполнению; `agent_ro` read-only — последняя инстанция.
- Dead loop защита детерминированна: retry-бюджет, бюджет в рублях и капы key-set
  живут в коде, модель их не переопределяет.
- Узлы тестируются по отдельности на фейковых портах; переходы — интеграционно;
  трейс читается как карта сцены.
- Замена движка возможна: узлы не знают о LangGraph (слои orchestration/composition).

**Отрицательные / риски:**
- Модель не выбирает инструменты сама — для задач, где свободный порядок был бы
  выгоден, маршруты надо закладывать заранее. На нашем скоупе (одиночный
  «вопрос → ответ») таких задач нет; появятся — revisit.
- Каждое новое ветвление = правка графа, а не промпта. Цена осознанная: ветвление,
  которое нельзя перепрыгнуть, стоит правки графа.

**Критерии пересмотра решения (revisit triggers):**
- Мультиагентность (open #2): вынесение `generate_sql`/`interpret_result` в отдельных
  агентов со своими SOP/памятью — пересмотр структуры графа, не принципа.
- Появление задач со свободным порядком исследования данных (exploratory-режим) —
  отдельный профиль графа или свободный ReAct-контур за явным флагом.
- История диалога (мультиход) — липкий scope/переписывание запроса до роутинга;
  граф усложняется входом, не отказом от контроля переходов.
