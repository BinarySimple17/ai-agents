# Бизнес-глоссарий (кураторские данные — ADR-003 §4)

> Формат: каждая запись — раздел `## [термин: <имя>] — таблица <таблица|null>`.
> Таблица — привязка для фильтра прав retrieval (`null` = общий документ);
> тело раздела — контент чанка для эмбеддера (префикс-заголовок остаётся в
> чанке — якорь термина, ACCURACY §6.2). Правит куратор; автонаполнение
> «успешным по трейсу» запрещено (ADR-003 §4).

## [термин: выручка] — таблица orders

Выручка — сумма `orders.total` по заказам: `SUM(o.total)`. `total` заказа —
сумма его позиций (`order_items.quantity * order_items.unit_price`), а не
отдельное поле прайса. Считать выручку по `products.price` нельзя — цена
позиции фиксируется в `order_items.unit_price` на момент продажи.

## [термин: заказ вне кампании] — таблица orders

`orders.campaign_id` NULLABLE: заказы, не попавшие ни в одну рекламную
кампанию, имеют `campaign_id IS NULL`. INNER JOIN с `campaigns` молча теряет
такие заказы. Вопросы «по всем заказам/всей выручке» требуют `LEFT JOIN`
кампаний (или расчёт без кампаний), а не INNER JOIN.

## [термин: клиент из РФ] — таблица customers

Страна клиента хранится в `customers.country` как код `'RU'`, а не
`'Russia'` (ловушка самокоррекции: фильтр `country = 'Russia'` честно
возвращает 0 строк). Демо-данные содержат также клиентов из `'DE'`
(Германия) и других стран — вопрос «клиенты из Германии» = `country = 'DE'`.

## [термин: премирован] — таблица bonuses

Премия сотрудника — строка в `bonuses` (сумма `amount`, период `period`).
«Сотрудник не был премирован» = LEFT JOIN `bonuses` по `employee_id` с
`WHERE b.bonus_id IS NULL` — классическая анти-джойн сцена демо-схемы.
`salary` (employees) — чувствительная колонка: вне прав обычных ролей
(ADR-005).

## [термин: позиция заказа] — таблица order_items

Заказ состоит из позиций `order_items` (`quantity`, `unit_price`); связь с
заказом — `order_items.order_id`. Агрегаты по товарам (количество, сумма)
считаются по позициям; связь позиции с товаром — `product_id` в `products`.
