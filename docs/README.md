## Приоритет источников при конфликте

1. **Канон S00** ([solution/sessions/S00_session.md](../solution/sessions/S00_session.md)) — стек, порты, контракты стыков и запреты проекта;
2. **ТЗ** ([prd.md](prd.md)) — живые прикладные требования: FR/NFR и матрица трассировки (изменения требований — сюда + затронутые ADR); исторические детали — полная спецификация `.docs/hw-01/README.md` (READ ONLY, вне гита, ≈89 КБ); [hw-01/README.md](../hw-01/README.md) — решение ДЗ-1 (ужатый артефакт сдачи); папки `hw-NN/` в целом — решения ДЗ NN;
3. **ADR** ([docs/adr/](adr/README.md)) — зафиксированные решения с обоснованием;
4. **ER-модель** ([docs/diagrams/er-data-model.md](diagrams/er-data-model.md)) — каноническая схема данных;
5. **ARCHITECTURE.md** — сводка, синхронизируемая с ADR;
6. Рабочие сессии (`solution/sessions/`) — история исполнения; задним числом не редактируются;
7. `DECISIONS.md` (корень) — оперативные решения сессий; если решение архитектурно значимое, оно переносится в ADR.

> **Канон архитектурных фактов — этот трекаемый пакет `docs/`** (prd.md, ADR, схемы, обвязка);
> `.docs/` — исторические документы READ ONLY (D-011): чтение исторических деталей разрешено,
> правки — только в docs/. `hw-01/README.md` — решение ДЗ (ужатая наружная версия). Пакет
> развивает канон до решений (ADR) и схем. При расхождении — правка затронутых ADR в одном
> заходе (правило R-P2 в [RISKS.md](RISKS.md)). Номера разделов вида «Канон: hw-01/README.md §N»
> в трассировке ADR указывают на публичную версию; полные подразделы исторически — `.docs/hw-01/README.md`.

Расхождение между источниками (или между документом и кодом) — не тихая правка: запись в [solution/FIXES.md](../solution/FIXES.md), решение владельца, синхронная правка всех затронутых мест в том же PR.
